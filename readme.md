В директории `examples` представлены ноутбуки с примерами работы с библиотекой. 
В тетрадках *.0 описаны основные концепции, идеи и примеры применений используемых абстракций, а в *.1 - подробное описание, как реализовывать свои имплементации используемых абстракций.

## 5.3.4 в конфигурации GenAI

`valtest_stat_significance` строит таблицу по каждой гипотезе и публикует p-value
и доверительные интервалы. По умолчанию `is_info=True` и светофор серый. Запись
`valtest_stat_significance` в общей конфигурации `test_desc.json` вызывает отдельную
функцию `valtest_stat_significance_legacy`.

Для обычного режима передайте `is_info=False`. По границам из v4 результат
зелёный при `p < 0,01`, жёлтый при `0,01 ≤ p ≤ 0,05` и красный при
`p > 0,05`. При отсутствии p-value используется серый.
Итоговый цвет соответствует основному `precomputed['p_value']` из первой строки,
а в таблице отображаются цвета всех гипотез и методов. Статистические расчёты
в обоих режимах одинаковы. Параметр `semaphore_threshold` задаёт границы обычного
режима и по умолчанию равен `(0.01, 0.05)`.

- Для порога передайте `value_threshold`. Для сравнения версий передайте
  `extra_samplers` и, если согласовано, `comparison_margin`. Для парных версий
  укажите `same_questions=True` и общий `id_column`, если его нельзя определить
  по идентификатору в данных.
- Укажите `metric_agg` или `metric_kind`. Для Accuracy, Precision, Recall и
  F1 передавайте эталон и предсказание либо пообъектные счётчики. В бинарном случае
  положительный класс задаётся `positive_label`. Для NER поддерживаются
  `extracted` и `target` штатного `NerSampler` и ключи `ner_exact_match_micro_f1`
  и `ner_partial_match_micro_f1`. По умолчанию сущности сопоставляются целиком с
  учётом повторов. Если зарегистрированный `scorer` задаёт собственную формулу,
  тест вычисляет её бутстрэпом. `metric_kind='custom'` также позволяет задать
  `calc_metric_fn`. Если scorer возвращает несколько значений, `main_metric`
  указывает нужный ключ, например `single_mean_final_metric` для `UniversalScorer`.
- `metric_thresholds` добавляет самостоятельные проверки бизнес-порогов. Можно
  добавить второй порог для основной метрики с той же формулой, включая формулу
  из `scorer`. Дополнительная Accuracy по бинарным оценкам использует
  `metric_value`, если этот столбец присутствует. `alternative` задаёт направление
  основной проверки. По умолчанию Уэлч и Уилкоксон
  для сравнения версий проверяют снижение относительно допустимой разницы.
  Для порога и критериев из таблицы метрик классификации используется
  верхняя альтернатива. `significance_level` добавляет текстовый вывод о H₀.
  При нескольких методах отчёт обозначает оцениваемые величины и поясняет, когда
  из результатов следует общий вывод. Для Уилкоксона и бутстрэпа среднего на одних
  вопросах выводы относятся соответственно к медиане и среднему парных разностей.
- Для расчёта требуется более 100 пригодных наблюдений в каждой выборке.
  Если точный критерий неприменим из-за нескольких испытаний на объект
  или ненулевого порога разности, используется бутстрэп по объектам.
  `bootstrap=True` добавляет бутстрэп к основному методу. При нескольких гипотезах
  из `methods` берутся подходящие для каждой гипотезы методы. Если подходящих нет,
  применяется её стандартный критерий. Если у бутстрэпа меньше двух объектов с
  ненулевым знаменателем или есть неопределённые перевыборки, таблица указывает
  причину отсутствия оценки. Точное p-value публикуется, когда его можно вычислить.

## Структура библиотеки

### Расчёты по трейсам без sberpm

`valtest_trace_connectivity` и `valtest_loop_duration_analysis` используют
собственные функции из `llm_val.utils.traces`. Для этих расчётов достаточно
`pandas` и стандартной библиотеки; устанавливать `sberpm` не требуется.
Сигнатуры двух `valtest_*`, формат `report` / `precomputed`, названия колонок
и передача готовых результатов сохранены.

Вспомогательные функции работают с DataFrame:

```python
from llm_val.utils.traces import (
    prepare_traces,
    extract_graph_components,
    calc_time_statistic,
    calc_loop_statistic,
)

traces = prepare_traces(data)
start_nodes, end_nodes, components = extract_graph_components(traces)
time_statistics = calc_time_statistic(traces)
loop_statistics = calc_loop_statistic(traces)
```

`prepare_traces` принимает имена колонок через `col_case`, `col_stage`,
`col_start_time`, `col_end_time`. По умолчанию это `trace_id`, `span_name`,
`start_time_ns`, `end_time_ns`. Числовое время интерпретируется как Unix-время
в наносекундах; также поддерживаются datetime и строки. Длительности считаются
в секундах. События сортируются по трейсу, началу, концу и имени ноды;
исходная таблица не меняется.

Реализация сохраняет прежние расчёты: направленный обход графа в порядке
появления нод, строгие границы квантилей 5% и 95%, пять показателей
зацикленности и их min-max нормализацию между нодами. Константные показатели
нормализуются в ноль. Воспроизведены и особенности прежнего алгоритма:
сдвиг на три события для «Пинг-Понга», разметка одиночных событий в показателе
произвольного цикла и граница общего индекса для возврата в начало.
Это замена зависимости, а не изменение определений метрик.

Значения сверены с расчётами из локальной поставки `sberpm 3.4.3`.
Контрольные входы и результаты находятся в
`unit_tests/data/traces_loop_statistics.json`; для их проверки исходная
библиотека не нужна. Прямые вызовы вспомогательных функций теперь принимают
подготовленный DataFrame вместо `DataHolder` / `Graph`.

```bash
cd unit_tests
PYTHONPATH=../src python -m pytest utils/test_traces.py \
    val_test/traces/test_valtest_trace_connectivity.py \
    val_test/traces/test_valtest_loop_duration_analysis.py
```

### Каталоги

Иерархия и описание директорий и файлов в библиотеке:
- model - Различные реализации моделей:
    - GigaModel.py - родительский класс, от которого должны наследоваться все реализации моделей;
    - BaseGigaModel.py - простейшая реализация модели;
    - MultiThreadGigaModel.py - простейшая многопоточная реализация модели;
    - ...
- sampler - Различные реализации sampler'ов:
    - Sampler.py - родительский класс, от которого должны наследоваться все реализации sampler'ов;
    - MMLUSampler.py - пример sampler'а для MMLU-датасетов;
    - RuBQSampler.py - пример sampler'а для RuBQ-датасетов;
    - ...
- scorer - Различные реализации scorer'ов:
    - Scorer.py - родительский класс, от которого должны наследоваться все реализации scorer'ов;
    - UniversalScorer.py - пример скорера;
    - ...
- val_test - Валидационные тесты:
    - data_quality - тесты на качество данных;
    - model_quality - тесты на точность модели;
    - ...
- utils - Вспомогательные штуки для работы библиотеки:
    - api.py - класс, реализующий функционал API GigaChat'а;
    - metrics.py - словари и реализации функций для подсчета метрик;
    - ssl_context.py - контекстный менеджер для выключения проверки ssl сертификата;
    - lib_vars.py - внутренние переменные для работы библиотеки;
    - report_helper.py - функции для помощи в составлении report'a;
    - ...

## Нейминг параметров:

"Строгие" названия параметров, верные для всех тестов:
- sampler - семплер;
- scorer - скорер;
- model - модель;
- data_type - название выборки (train/val/test/oot);
- metric_name - название метрики;
- metric_agg - способ агрегации метрики;
- semaphore_threshold - трешхолды светофоров;
- greater_is_better - верно ли, что чем больше метрика, тем лучше;
- is_info - тест информационный или нет.
